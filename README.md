# Weather Conditions and Personal-Injury Traffic Accidents in Oslo and Akershus

**An open-data analytics case study (2014–2024)**  
**MIS404 Business Analytics · University of South-Eastern Norway (USN) · Spring 2026 · Team coursework**

This project investigates associations between monthly weather conditions and **personal-injury traffic-accident counts** in Oslo and Akershus, Norway. It combines accident aggregates from **TRINE / Statens vegvesen** with weather observations from **MET Norway Frost API**, aggregated from three regional stations (Oslo Blindern, Gardermoen, Lillestrøm).

The goal is transparent descriptive and predictive analysis—not causal identification or crash-level risk prediction.

## Research workflow

1. Retrieve daily air temperature and precipitation from the three Frost stations.
2. Aggregate station observations to a daily regional estimate and then to monthly mean temperature and monthly total precipitation.
3. Load monthly TRINE/Statens vegvesen accident counts (fatal, serious injury, minor injury); exclude property-damage-only incidents.
4. Merge by year and month, create cyclic seasonality features and a year trend.
5. Compare Poisson regression, negative binomial regression, and a random forest using a **chronological 80/20 holdout** (105 training months; 27 test months in the original study).
6. Evaluate MAE and RMSE; interpret regression coefficients as **associations**, not causal effects.

### Findings reported in the original course report

| Model | Holdout MAE | Holdout RMSE |
|---|---:|---:|
| Poisson regression | 10.54 | 14.12 |
| Negative binomial regression | 10.42 | 13.91 |
| Random forest regression | **9.50** | **11.43** |

The original course report used **132 monthly observations** from 2014–2024 and reported that temperature, seasonality, and long-term trend were more informative than monthly total precipitation in this dataset. Those figures are **historical results from the original group report**, not metrics regenerated by this repository's new portable refactor. No causal relationship is claimed.

## Repository contents

- `notebooks/weather_traffic_analysis_colab.ipynb`: Colab notebook with saved outputs and API credentials removed for public release. It prompts for the TRINE CSV.
- `src/weather_traffic/analysis.py`: Python implementation of the data preparation and modeling workflow, maintained separately from the Colab notebook.
- `scripts/run_analysis.py`: command-line entry point.
- `tests/`: offline checks with **synthetic data**, not real accident data.
- `.env.example`: names of environment variables needed for optional Frost API retrieval. Never commit real credentials.

## Quick start

Requires Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest -q
```

### Input requirements

The original TRINE accident export is a UTF-8 (with optional BOM), semicolon-delimited CSV with columns:

`År`, `Måned`, `Dødsulykke`, `Ulykke med hardt skadde`, `Ulykke med lettere skadde`.

Month names are Norwegian (`Januar` through `Desember`). Only the aggregated monthly counts should be supplied, not individual personal records.

For offline runs, supply `weather_daily.csv` with columns `station`, `date`, `mean(air_temperature P1D)`, and `sum(precipitation_amount P1D)` (date in ISO format). For an online run, MET Norway Frost can be queried directly.

### Offline run with existing weather observations

```bash
python scripts/run_analysis.py --accidents data/trine_monthly.csv \
  --weather-daily data/weather_daily.csv --outdir outputs
```

### Fetch weather using Frost API

```bash
export FROST_CLIENT_ID='your-frost-client-id'
# FROST_CLIENT_SECRET is optional depending on your Frost credentials
python scripts/run_analysis.py --accidents data/trine_monthly.csv \
  --fetch-frost --outdir outputs
```

Credentials are read from environment variables, never embedded in notebooks, repository files, or output logs.

Typical outputs: `final_dataset.csv`, `monthly_weather.csv`, `model_comparison.csv`, `poisson_coefficients_irr.csv`, `random_forest_feature_importance.csv`, `summary.json`, and a holdout prediction plot. The code validates input columns and chronology and fails on duplicate month rows.

## Limitations and responsible interpretation

- This is a **team coursework study**, not a peer-reviewed publication or a deployed safety system.
- Monthly regional observations cannot capture weather at each crash scene or short-term weather events.
- Traffic volume/exposure, road infrastructure, driving behavior, and other confounders were not controlled.
- Three stations approximate regional weather; missing observations and subsequent data revisions can affect re-runs.
- This is association analysis; do not infer that changing temperature *causes* any particular number of traffic accidents.
- Holdout comparisons use only 27 months; do not infer production forecasting accuracy or generalization to other regions.

**Data provenance:** MET Norway [Frost API](https://frost.met.no/) and Statens vegvesen/TRINE aggregated data export supplied to the original student team. Respect the source licensing and terms before redistributing any data.
